## LatchHook.sol

Inherits `BaseHook` from `uniswap-hooks` (Solidity `^0.8.26`). The lock.

<Tabs>
  <Tab title="Permissions">
    `getHookPermissions()` enables **only** `beforeRemoveLiquidity = true` — everything else is `false`. It is deliberately not a fee hook and never touches the swap fee.
  </Tab>
  <Tab title="Schedule">
    `setSchedule(PoolKey key, uint64 cliffTime, uint64 periodLength, uint32 periodsCount, uint256 totalLocked)` writes the schedule **exactly once**. Reverts `ScheduleExists` if already set; reverts `InvalidSchedule` if `periodLength`, `periodsCount`, or `totalLocked` is `0`. Records `creator = msg.sender` for transparency only — no privilege. Emits `ScheduleSet(poolId, creator, totalLocked, cliffTime, periodLength, periodsCount)`.
  </Tab>
  <Tab title="Enforcement">
    `_beforeRemoveLiquidity(...)`: pools with `totalLocked == 0` and non-removals pass through. Otherwise `removeAmount = uint256(-liquidityDelta)`, `released = releasedAmount(now)`, `already = removedSoFar[id]`; if `already + removeAmount > released` it reverts `RugBlocked(requested, alreadyRemoved, released)`; else updates `removedSoFar` and emits `LiquidityReleased(poolId, amount, cumulativeRemoved, released)`.
  </Tab>
  <Tab title="Storage & views">
    Storage: `mapping(PoolId => Schedule) schedules`; `mapping(PoolId => uint256) removedSoFar`. Views: `releasedAmount(PoolId id, uint256 timestamp)` and `wouldExceedLock(PoolId id, uint256 amount, uint256 timestamp)`.
  </Tab>
</Tabs>

<Warning>
  `RugBlocked` is a custom **error**, not an event. A reverting tx rolls back its logs, so the onchain artifact of a blocked rug is the **failed transaction** carrying the `RugBlocked` revert reason — which v4 re-wraps as `WrappedError`. Index failed txs, not events, to surface blocked rugs.
</Warning>

<Info>
  Enforcement is pure pool state: no oracle, no identity check, no admin key. The gate fires regardless of who owns or transfers the LP position — transferring the LP NFT does not bypass the lock.
</Info>

### Schedule type and math

The `Schedule` struct lives in `libraries/LatchTypes.sol`; all liquidity is in v4 liquidity units (L).

```solidity
struct Schedule {
    uint64  cliffTime;
    uint64  periodLength;
    uint32  periodsCount;
    address creator;
    uint256 totalLocked;
}
```

`LatchMath.releasedAmount(Schedule s, uint256 timestamp)` returns `0` before `cliffTime`, then unlocks one equal step (`totalLocked / periodsCount`) per `periodLength` elapsed after the cliff, reaching `totalLocked` after `periodsCount` steps. It is **stepwise, not continuous**.

## LatchRegistry.sol

The verify-before-you-buy directory.

```solidity
function register(/* ... */) external;          // reverts AlreadyRegistered on dup
function isVerified(PoolId id) external view returns (bool);
function getEntry(PoolId id) external view returns (Entry memory);
```

Defines the `Entry` struct and emits `PoolVerified`. The frontend reads it directly from chain.

## LatchLauncher.sol

The one-transaction launch.

```solidity
function launch(LaunchParams p) external returns (PoolId id, address token);
```

Deploys the token, initializes the pool on the `PoolManager` with the Latch hook, seeds liquidity, writes the schedule via the hook, and lists the pool in the registry — atomically. Defines `LaunchParams` and emits `PoolLaunched(poolId, token, creator, liquidity)`. Implements `unlockCallback` for v4's unlock pattern, which reverts `NotPoolManager` if called by anyone other than the `PoolManager`.

## DemoToken.sol

A fixed-supply OpenZeppelin ERC-20 with **no mint, no blacklist, no pause, no owner privileges**.

<Note>
  Rationale: a malicious token would defeat any LP lock, so Verified launches use a safe template. See [Honest Scope](/concepts/honest-scope).
</Note>
